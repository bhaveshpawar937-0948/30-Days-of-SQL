\## 🧠 What is UNION?



`UNION` combines the output of two or more `SELECT` queries.



Example:



```sql

SELECT name

FROM students



UNION



SELECT name

FROM alumni\_students;

```



The results are combined into one column.



`UNION` automatically removes duplicate rows.



\---



\## ⚡ What is UNION ALL?



`UNION ALL` works similarly, but it keeps every row, including duplicates.



```sql

SELECT name

FROM students



UNION ALL



SELECT name

FROM alumni\_students;

```



This is useful when duplicate values are meaningful or when we want to preserve the complete data.



\---



\## ⚖️ UNION vs UNION ALL



| Feature              | UNION | UNION ALL |

| -------------------- | ----- | --------- |

| Combines result sets | ✅     | ✅         |

| Removes duplicates   | ✅     | ❌         |

| Preserves duplicates | ❌     | ✅         |

| Usually faster       | ❌     | ✅         |



`UNION ALL` generally requires less processing because SQL does not have to remove duplicates.



\---



\## 📏 Rules for UNION



Queries combined using `UNION` should follow a few important rules.



\### Same Number of Columns



Both queries should return the same number of columns.



Correct:



```sql

SELECT name, city

FROM students



UNION



SELECT name, city

FROM alumni\_students;

```



Incorrect:



```sql

SELECT name, city

FROM students



UNION



SELECT name

FROM alumni\_students;

```



\---



\## 🔢 Compatible Data Types



Columns in corresponding positions should contain compatible data types.



For example:



```text

Column 1 → text

Column 2 → text

Column 3 → numeric

```



in both queries.



\---



\## 🏷️ Adding Source Labels



A useful analytical technique is adding a column that identifies where each row originated.



```sql

SELECT

&#x20;   name,

&#x20;   'Current Student' AS source

FROM students



UNION ALL



SELECT

&#x20;   name,

&#x20;   'Alumni' AS source

FROM alumni\_students;

```



This makes combined datasets easier to understand.



\---



\## 🔃 Sorting Combined Results



`ORDER BY` should normally appear after the complete set operation.



```sql

SELECT name

FROM students



UNION



SELECT name

FROM alumni\_students



ORDER BY name;

```



This sorts the final combined result.



\---



\## 💡 Where UNION is Useful



Set operations are useful when combining:



\* Current and archived records

\* Customers from different systems

\* Monthly or yearly datasets

\* Employees from multiple branches

\* Active and former students

\* Sales from different regions

\* Results generated by separate conditions
